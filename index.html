            시작하기
            
        
              
          
            1. 저장소 폴더에서 아래 명령을 실행하고 결과를 파일로 저장합니다. git log --no-merges --date=short --name-only --since="5 weeks ago" --format="@@%h|%ad|%an|%s" > log.txt
              2. 
          
            2. log.txt 를 화면에 끌어다 놓습니다. 일반 git log, --stat, --name-status, --numstat, --oneline 출력도 읽습니다.
              3. 
          
            3. 주차를 고르고, 주제마다 메모의 왜 와 상태("완료: …", "예정: …")를 채웁니다. 지난주에 이어진 주제는 지난주 '왜'를 이어받습니다.
              4. 
          
            4. 요약이 검증을 통과하면 PPTX · Markdown 으로 내보냅니다.
              5. 
        
            
        
            숫자 사실 검증은 무엇을 막나요?
            
        
            요약(제목 · 3줄)에 나온 숫자 · 날짜 · 소수, "세 배" "절반" 같은 글자 수량, 완료 · 검증 · 배포 같은 상태어, 단축 · 향상 · 수율 · 가동률 같은 효과어가 커밋 제목 · 메모에 없으면 막습니다. 막힌 표현과 이유는 요약 아래 표에 나옵니다. 숫자가 맞다면 메모에 적어 근거를 남기세요.
            
        
            영역 사전
            
        
            설정 › 영역 사전에서 모듈 규칙(파일 경로 접두어 · 제목 단어), 설비 번호 패턴(예: 3호기, EQ-03), 현장 이슈 번호 패턴(예: FI-238, #123)을 정합니다. 같은 이슈 번호를 가진 커밋은 제목이 달라도 한 주제로 묶입니다. 바꾸기 전에 같은 데이터로 전 / 후를 비교해 보여줍니다.
            
        
            LLM 은 꼭 필요한가요?
            
        
            아니요. 키가 없어도 규칙 기반 요약 · 검증 · 내보내기가 모두 됩니다. LLM 요약은 Shadow 칸에만 나오고, 검증을 통과한 것만 채택할 수 있습니다. Shadow 기록이 10건 이상이고 통과율이 80% 이상이면 "LLM 채택으로 전환"이 켜지며, 언제든 되돌릴 수 있습니다.
            
        
            내 PPTX 양식
            
        
            설정 › PPTX 양식에서 "자리표시자 예시 양식"을 받아 내 양식에 같은 자리표시자를 넣고 올리세요. {{title}} 이 있는 첫 슬라이드가 내지로 쓰이고 주제 수만큼 복제됩니다.
            
        
            문제 해결
            
        
              
          
            • "상대 날짜" 오류: 명령에 --date=short 를 붙이세요.
              • 
          
            • 한글이 깨짐: UTF-8 로 저장하세요. EUC-KR 파일은 자동으로 다시 읽어 봅니다.
              • 
          
            • Ollama 연결 실패: Ollama 를 실행하고, 이 사이트 주소를 OLLAMA_ORIGINS 에 넣어 다시 시작하세요.
              • 
          
            • 데이터 옮기기: 설정 › 데이터에서 백업(JSON)을 내보내 다른 브라우저에서 가져옵니다.
              • 
        
            
      
            
      
            
        
            Getting started
            
        
              
          
            1. In your repository run the command below and save the output. git log --no-merges --date=short --name-only --since="5 weeks ago" --format="@@%h|%ad|%an|%s" > log.txt
              2. 
          
            2. Drop log.txt onto the page. Plain git log, --stat, --name-status, --numstat and --oneline output also work.
              3. 
          
            3. Pick a week and fill each topic's why and status ("Done: …", "Next: …"). Topics continued from last week take over last week's 'why'.
              4. 
          
            4. When the summaries pass the check, export PPTX or Markdown.
              5. 
        
            
        
            What does the fact gate block?
            
        
            Numbers, dates and decimals, quantities written in words ("three times", "half"), status words (done, verified, deployed) and effect words (faster, yield, uptime, throughput) in the title or lines are blocked when they are not in the commit subjects or memo. The blocked phrases and the reason appear under the summary. If a number is real, write it in the memo as evidence.
            
        
            Domain dictionary
            
        
            Settings › Dictionary sets module rules (path prefixes · subject words), the equipment ID pattern (e.g. EQ-03, Tool 2) and the field issue pattern (e.g. FI-238, #123). Commits that share an issue ID form one topic even with different subjects. Before a change is applied you see before / after on the same data.
            
        
            Do I need an LLM?
            
        
            No. Without a key, rule-based summaries, checks and export all work. LLM summaries appear only in the Shadow column and can be adopted only when they pass. With 10+ Shadow runs and a pass rate of 80%+ the "Switch to LLM adoption" button turns on, and you can always roll back.
            
        
            My PPTX template
            
        
            In Settings › PPTX style, download the placeholder sample, put the same placeholders in your template and upload it. The first slide with {{title}} is the content slide and is copied once per topic.
            
        
            Troubleshooting
            
        
              
          
            • "Relative date" error: add --date=short to the command.
              • 
          
            • Broken Korean text: save as UTF-8. EUC-KR files are re-read automatically.
              • 
          
            • Ollama unreachable: start Ollama with this site's origin in OLLAMA_ORIGINS.
              • 
          
            • Moving data: export a backup (JSON) in Settings › Data and import it in the other browser.
